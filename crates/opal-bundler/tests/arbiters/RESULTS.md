## What this shows

- **The disagreements are about semantics, not syntax.** Where esbuild or rollup diverge, it is on what this contract is about: evaluation order in a cycle (`esm-cycle-order`), the TDZ in a lazy cycle and link-before-evaluate (`lazy-cycle-tdz`, `lazy-link-before-evaluate`, esbuild), `.name` after renaming (`esm-name-collisions`), which names a namespace holds when `export *` reaches one twice (`esm-star-namespace-cells`, and `esm-namespace-nested-ambiguous` for esbuild), CommonJS interop and `require()` of builtins from ES module output (`cjs-loader`, `esm-imports-cjs`, `json-modules`), `import.meta.url` and `__filename` naming the bundle (`builtins`, `import-meta`), how `require()` reads a package's `main` (`cjs-nested-package-main`), and sloppy mode (`cjs-sloppy`, which neither builds).
- **Where opal refuses, bundling anyway mostly changes the program.** Of the fixtures opal refuses, the other two bundlers' output diverges from Node's run on most: the program fails to link in Node, and the bundle runs. The exception is `refuse-deep-nesting`, which Node cannot compile either: esbuild's bundle overflows the stack as the program does, and rollup crashes building it.
- **Some refusals are conservative.** `refuse-tla-outside-entry` (both), `refuse-direct-eval` (esbuild), `refuse-lazy-top-level-arguments` (rollup), and `refuse-star-cycle-ambiguous` (rollup) bundle into something equivalent on these programs: a top-level `await` with no sibling to interleave, an `eval` that reads a name no renaming touched, a module rollup does not run in a function, and an ambiguous name that V8 gives whichever namespace of an `export *` cycle it builds second, which with this program's import order is the one rollup gives it. opal refuses the class of program, because it cannot tell these instances from the ones where it would matter.
