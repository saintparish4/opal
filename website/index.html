Opal is a crash‑safe JavaScript toolkit. One graph.

A package manager today, with a runtime, bundler and test runner planned, in a single binary. Use opal install in an existing Node.js project: it installs what npm would, from one store shared by every project.

Install Opal v0.3.1

curl -fsSL https://raw.githubusercontent.com/saintparish4/opal/master/install.sh | bash
View install script ↗

Linux x64 and arm64 (glibc 2.39 for v0.3.1), macOS x64 and Apple Silicon. Checked against the release's SHA256 checksums.

On Windows, Opal runs inside WSL2: open a WSL terminal and run the same command. Native Windows isn't supported yet.

    Tested, not claimed
    
        
    Built to be trusted first.
    
        
    A package manager that is fast and occasionally wrong is not fast. These are the properties Opal tests for, with the numbers from the test runs.
    
      
    
      
    
        
    
          
    432/433
    
          
    The versions npm picks
    
          
    On a 364-package Next.js app, 432 of npm's 433 package versions are identical. The differences are documented, and a CI job fails if a new one appears.
    
        
    
        
    
          
    332kills
    
          
    Kill it anywhere
    
          
    Every write is atomic and the linker is a reconciler. In one soak, 332 SIGKILLs interrupted a running install; re-running converged on a clean tree every time.
    
        
    
        
    
          
    31MB
    
          
    Small while it works
    
          
    Peak memory installing express was 31 MB, against 154 MB for npm and 41 MB for bun: the least of the five. On a Next.js app it was second lowest, 499 MB against npm's 432 MB. Same preliminary run as the charts below.
    
        
    
        
    
          
    1store
    
          
    One copy of every file
    
          
    Packages are verified against the registry's integrity hash, stored once per machine, and hardlinked into each project.
    
        
    
      
    
    
    

    
    
    
      
    
        
    
          
    opal install Preliminary
    
          
    Fastest where you reinstall. Not yet where you download.
    
          
    Cold cache, CI, a reinstall and a no-op, on a Next.js app and on express, against npm, pnpm, yarn and bun at their defaults. Opal's losses are on the same page as its wins.

    Read before you switch
    
        
    What it doesn't do yet.
    
        
    Worth knowing before you point Opal at a project. The first three are asserted by tests, so the suite says what doesn't work as plainly as what does.
    
      
    
      
      
        
    • Install scripts don't run. Packages that ship prebuilt binaries work. A package that compiles with node-gyp installs but isn't built, and opal install names it every time.
      • 
        
    • Peer dependencies aren't installed. They are recorded, not added to the tree the way npm 7 and later add them.
      • 
        
    • git: and file: dependencies are refused. Dependencies come from a registry only.
      • 
        
    • No add, remove or update. Edit package.json and run opal install. Commands that aren't built aren't in the binary.
      • 
        
    • First installs are slow in v0.3.1. It downloads one package at a time, 4–7× slower than npm on a cold install. The fix is on master and ships in v0.4.0.
      • 
        
    • Linux needs a recent glibc. v0.3.1's binaries need glibc 2.39 (Ubuntu 24.04 or newer); the next release goes back to 2.34. Alpine and other musl distributions aren't supported.
